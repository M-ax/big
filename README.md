### Big — VLC-powered SMB media library

This is a standalone Android app using LibVLC, not a fork of VLC's Android interface. The intended library will index a selected SMB folder and generate searchable topic/person shortcuts from recurring filename and path text.

### Playback foundation

- Open audio/video through Android's file picker, or open a direct network media URL.
- LibVLC `3.7.0`, the engine dependency used by [VLC Android 3.7.1](https://github.com/videolan/vlc-android/blob/3.7.1/build.gradle).
- Icon controls in one bottom row: tracks on the left, centered ±10-second/playback controls, speed immediately to their right, and screen fit on the far right. Elapsed/total time sits to the right of the seek bar, not above it. Edge double taps also skip ten seconds.
- Horizontal swipe previews the actual frame with millisecond target time in gray and signed change in white, then commits on release. The zero-based accelerated curve has no three-second minimum jump. Drag down while seeking (18% of the viewport) for fine adjustment: one nominal source frame per 4 dp; return upward to leave fine mode without jumping. Unknown frame rates use millisecond adjustment. Live/nonseekable inputs disable seeking.
- Timestamp-aware adaptive touch filtering suppresses stationary jitter without heavy fast-swipe lag. Finger release commits the last displayed MOVE target, ignoring lift-off coordinate roll. Canceled/multitouch gestures restore the starting position; prior play/pause intent is preserved.
- Gesture feedback uses a GPU-blurred, darkened video backdrop; its center replaces the sharp image completely. Blur strength and blending taper smoothly at rounded edges while the overlaid text stays sharp. Normal VLC playback feeds an external texture into a flat, orthographic EGL filter pass—no bitmap capture, CPU readback, or fixed-rate polling. Extracted seek frames use a GPU texture through the same blur and fit pipeline. Audio-only/unavailable video uses a faint tint.
- Incoming video frames drive the filter context, including fractional/variable-rate delivery and playback-speed changes; there is no fixed display-rate render loop. Paused feedback/layout changes request a single redraw, and paused seeks/subtitle changes can update the still frame. The app also requests the video's effective frame rate from Android, but the display chooses a supported refresh rate. Slow hardware may drop frames; zero-copy texture sharing does not guarantee 4K/HDR or every device's maximum-rate performance. This output uses an 8-bit SDR EGL surface; HDR passthrough/protected-content output is not implemented.
- Swipe vertically on the left for window-only brightness and on the right for Android media volume. Volume is capped at the device maximum; no amplification boost.
- Tap to toggle controls without leaving fullscreen; double-tap the center for play/pause. Controls auto-hide during playback and can be locked. Android bars remain available through an explicit edge swipe.
- The header shows the filename (including document-provider display names), not the full URL. Overflowing names briefly scroll left and back right while visible; system-disabled animations are respected.
- Embedded audio/subtitle track selection, 0.25×–2× speed, and three screen-fit modes.
- Display aspect overrides are reduced before reaching VLC's native geometry arithmetic, including non-square pixels and rotated display axes. Decoded seek previews use the same source display aspect instead of assuming their resized bitmap dimensions describe the intended picture shape.
- Fill normally uses VLC's native crop. Small videos that would exceed VLC's hard-coded 10× zoom limit instead use uniform center cropping of its best-fit output in the existing GL pass, without stretching or a second render loop.
- Audio focus, headphone-disconnection pause, foreground-only playback, rotation handling, and position/pause restoration when Android recreates the player.

Gesture directions and the accelerated seeking curve follow VLC's conventions. Sensitivity is screen-relative rather than VLC's physical-distance calibration; this is **not yet complete VLC feature parity**. Background playback/media notifications, picture-in-picture, casting, playlists, external subtitles, audio/subtitle delay, equalizer, and the remaining VLC settings are not implemented.

### Precise seek previews and latency

- LibVLC remains the playback engine. Its precise paused timestamp seek can skip some B-frames, so local/content and authenticated SMB inputs also use a retained Android frame retriever for gesture previews and paused seeks. It selects the closest decoded presentation timestamp, not just a keyframe. Decoding stays off the UI thread, obsolete requests are discarded, and only the latest target is queued.
- Supported paused seeks update the exact preview and displayed position without repeatedly flushing VLC's paused hardware decoder. Only the last target is committed to playback on resume, preventing the hardware input-buffer stall reproduced with rapid paused HEVC seeks. Unsupported extraction still falls back to VLC; pause, cancellation, backgrounding, and recreation preserve the selected position.
- A **32 MiB / 64-entry**, memory-only decoded-frame LRU warms up to four neighboring frames while seeking and is discarded when the player is no longer visible. Preview bitmaps are capped at **1920×1080**, aspect-preserving, software ARGB; normal playback keeps its original resolution. Codec-native I/P/B reference management is left to the decoders rather than duplicating an unsafe compressed-frame parser. The bitmap cache excludes native decoder buffers, a retained/uploading frame, and GPU memory.
- Exact extraction is limited to Android-supported formats/codecs and seekable local/content/private SMB descriptors. Unsupported extraction falls back to LibVLC timestamp seeking with a visible hint. Nominal frame-rate stepping is not a full variable-frame-rate PTS index; universal frame-perfect selection, HDR fidelity, and embedded subtitles in extracted stills are not guaranteed. Normal playback retains VLC subtitle support.
- Decoder previews are coalesced at 80 ms minimum intervals, with a 250 ms slow-frame guard. Local/private-SMB VLC caching is reduced to 150 ms; other network protocols retain their prior buffering. Source-rate metadata from the frame retriever refines the gesture grid when available, without changing VLC's normal demux selection or playback cadence.
- GPU rendering remains frame-driven with no second vsync wait. Diagnostic callback-to-EGL-swap timing measures submission only, not network arrival, decode time, GPU completion, or physical display scanout.

### SMB share browser

- Tap **Browse SMB share** to open **Local SMB Shares**. Discovery starts automatically after local-network permission is granted. Select a discovered server to prefill **Add SMB Share**, then log in with username/password and an optional domain, or choose guest access. **Add SMB Share** also allows manual entry of a hostname/IP (optionally `:port`) or full folder address.
- Discovery combines Android DNS-SD/mDNS (`_smb._tcp`) advertisements with unauthenticated SMB2 negotiation on port 445. It uses only the current Wi-Fi/Ethernet network, not cellular or VPN, and discovers IPv4 endpoints. IP checks cover the private/link-local subnet, limited to the containing `/24` on larger networks (up to 254 addresses, excluding this device, network and broadcast addresses). Advertisements can supply names and custom ports; otherwise rows show IP addresses. Share names are listed after login, not anonymously scanned.
- A discovery pass lasts up to 20 seconds with bounded parallel connections and 600 ms probe deadlines. **Stop discovery**, leaving the screen, or losing the network cancels work; rotation retains the scan and results. **Refresh** clears the previous snapshot and searches again. Permission denial, no LAN, incomplete discovery, and empty results provide manual-entry guidance. Multicast filtering, client isolation, firewalls, IPv6-only hosts, other subnets, and non-advertised custom ports may require manual entry.
- A server address such as `smb://nas` lists its disk shares. A full address such as `smb://nas/Media/Movies` opens that folder directly, which also works when share enumeration is blocked. UNC addresses such as `\\nas\Media\Movies` are accepted. For URL addresses, encode literal `#` and `%` in names as `%23` and `%25`; filenames returned by the browser are handled automatically.
- Select a share, navigate folders, use **Up** or Back, refresh, retry errors, and tap a media file to play it with the existing VLC controls. Other file types can be attempted after confirmation. Empty folders, unavailable servers, invalid logins, denied permissions, and missing folders have distinct feedback.
- Tap the floating star at the bottom right to favorite the current successfully loaded share/folder. Favorites persist on the home page, where they can be opened or removed. Server roots and failed/loading locations cannot be favorited; adding the same folder again does not duplicate it.
- Favorites retain their login using Android Keystore AES-GCM encryption, bound to the exact favorite folder. Opening a favorite can reconnect after the process has ended, without putting passwords in the login fields or intents. Removing a favorite removes its saved credentials; failed authentication or an unavailable encryption key falls back to manual login. Non-favorited logins are not saved.
- The connected heading reads **SMB &lt;hostname/IP&gt;**. The complete title/path/back/up/refresh/disconnect panel scrolls away downward and returns immediately when scrolling upward, even deep in a folder. Login fields remain scrollable; the favorite button remains floating.
- Each browsed folder remembers its visible row and pixel offset, restored during layout before the first list frame. Independent positions survive back/up navigation, refresh/retry, and activity recreation through browser memory and Android saved state, not a permanent on-disk history. Changed listings retain the same filename anchor when possible and otherwise clamp to an available position.
- Folders have leading folder icons; video and audio files have type icons with extension badges. Folders come first, then media, then other files below one compact, non-clickable separator. Each group uses case-insensitive natural name sorting (`2` before `10`, including multiple number runs such as `S2E10`); otherwise-equivalent numeric names prefer fewer leading zeros, then use a case-sensitive tie-break. Share names use the same ordering.
- Network work runs off the UI thread. Rotation retains the active connection; cancellation/disconnection discards stale results. Individual SMB requests have 10-second timeouts; DNS lookup and very large directory listings can take longer.
- Active credentials remain in process memory; only favorited-folder logins are saved encrypted and excluded from backup/device transfer. The player receives an opaque session handle, never a password-bearing URL. Disconnecting ends the active session but does not forget a favorited login; remove the favorite to forget it. Credentials and the unvalidated address field are excluded from Android saved state/autofill. LibVLC uses its memory-only keystore.
- Browsing uses `jcifs-ng 2.1.10`, negotiating **SMB 2.02–2.1**, with SMB1 and silent guest fallback disabled. SMB3-capable servers must permit SMB2; SMB3-only/encryption-required shares and DFS referrals are not supported. Use a trusted LAN or VPN. Android 17+ requests local-network permission for discovery and on Connect if still needed.
- General connection profiles, file management, and indexing are not part of this browser. Integration is verified against the local Samba fixture and an Android-advertised SMB service, not yet your particular NAS/server.

### SMB seek buffering

- Authenticated/guest SMB browser playback reads through a seekable Android proxy descriptor and a private, memory-only cache; no seek-cache file is created. LibVLC still handles demuxing, decoding and playback controls.
- Playback and preview extraction have independent proxy descriptors/file positions over that shared cache. A duplicated descriptor is not independent: Android's seek-then-read frame extraction would otherwise reposition VLC's sequential reader, corrupting demux input and causing freezes, missing audio, or fatal playback errors after seeking.
- Once the normal 150 ms decoder buffer is full and playback is active, a background reader aggressively fills both sides of the current position, nearest blocks first: an estimated five minutes or **128 MiB per side**, whichever is smaller. For heap safety, each side is additionally capped at **1/16 of the app's maximum heap**, rounded down to 256 KiB blocks (minimum one). Slots allocate lazily; the total slot budget is at most **257 MiB**, including the 1 MiB foreground allowance, plus two 256 KiB transfer buffers and metadata. The decoded-frame cache and native/GPU buffers are separate.
- Time-to-byte windows use file size and duration, so five-minute coverage is approximate for variable-bitrate/container layouts. The byte cap is strict. Cached seeks avoid SMB downloads but still require keyframe decoding; instantaneous seeking is not guaranteed. Uncached seeks fetch normally, and the window moves with playback.
- Ordinary prefetch pauses when playback pauses or is buffering. During a seek gesture, a smaller **2 MiB per side** estimated target window warms even while paused, subject to the heap cap, and normal playback events cannot overwrite that hint. Commit/cancel restores normal prefetch gating. Foreground misses fetch only missing requested bytes instead of waiting for a whole 256 KiB block; initialized slices are safely merged. When the player is no longer visible (`onStop`), all app-cache byte/frame references are discarded without waiting for network/native decoding; late reads cannot repopulate the hidden cache. Pausing while still visible retains useful data. Returning starts with an empty app cache and preserves playback position; closing releases the readers too. Garbage collection reclaims discarded heap storage, and in-flight/native/GPU resources finish their asynchronous cleanup. Android manages its separate proxy-descriptor page cache. Cache data is never persisted or backed up.
- This extra cache applies to files opened through an SMB session. Local files and other network protocols retain their normal LibVLC/OS buffering; live streams and unknown-duration media do not receive speculative time-window prefetching.

### SMB indexing — deferred

Recursive scanning, the persistent searchable index, and automatic topics/people menus remain deferred. For that stage, provide the server/share and folder path plus representative filenames and desired topic/person labels. Enter passwords only in the app, not in source code or chat.

Network media URLs are not saved as history or displayed in full in the player title; explicitly favorited SMB folder URLs are saved locally. Embedded username/password URLs are rejected. Query tokens may still be handled by LibVLC, so avoid collecting or sharing raw engine logs containing private URLs. HTTP is enabled for local servers; use HTTPS where supported. No broad storage or system-brightness write permission is requested.

### Build and verification

Use Android Studio with the project SDK installed. The existing configuration requires Android API 37 for compilation, API 36+ devices, Gradle 9.6.0, and JDK 25. Set `JAVA_HOME` to your Android Studio JBR when running from PowerShell.

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Run the `app` configuration in Android Studio. The APK is at `app\build\outputs\apk\debug\app-debug.apk`.

Unit tests cover playback calculations, URL/path escaping and traversal rejection, SMB configuration/resource cleanup, session-token isolation, discovery subnet bounds, and SMB2 response validation/timeouts. Device tests verify live mDNS discovery and address handoff, discovery state/cancellation, login UI, credential non-restoration, real content-URI/HTTP/SMB playback, controls, navigation, errors, and rotation. Discovery UI tests require Wi-Fi or Ethernet (the emulator's AndroidWifi works). Instrumentation disables animations to avoid system dim-layer transitions intercepting taps.

GPU tests verify actual blur pixels, edge feathering, fine-detail suppression, frame-driven scheduling, and resource release. Real-video tests cover 23.976 fps, speed-adjusted cadence, 60 fps with/without blur, embedded subtitles, fit modes, and rotation. Run cadence tests on a hardware-accelerated emulator (`-gpu host`) or capable physical device: software GPU emulation can be slower than the source even without blur. Synthetic filter fixtures can be regenerated with FFmpeg 8 using `tools\video-test\generate.ps1`.

`SeekLatencyTest` checks decoded pixels in both seek directions using a frame-number barcode: 24 fps H.264 with four-second GOPs and B-frames. It also verifies one-frame gesture movement, lift stability, cancellation, background/resume, and handoff to playback. Regenerate the fixture with `tools\video-test\generate-seek.ps1` (non-overwriting). `SeekFrameExtractorTest` covers cache bounds, generation cancellation, descriptor ownership, and unsupported inputs; `SmbBufferIntegrationTest` also exercises extraction through the real private SMB descriptor.

Video fixtures under `app/src/androidTest/assets/` are intentionally not tracked. Regenerate the synthetic fixtures with the scripts and FFmpeg command documented here before running device tests. The supplied `aspect-ratio-failing-example.mkv` and `real-world-sample.mp4` must be obtained separately and placed in that directory for the regression tests below; they may contain copyrighted material and must remain local.

`VideoAspectRegressionTest` uses the supplied 720×576 HEVC Main 10 MKV (SAR 16:15, DAR 4:3), plus the rotated synthetic fixture. `RepeatedSeekRegressionTest` uses both supplied videos locally and over SMB: repeated distant scrubs, early release, ±10-second buttons, paused seeks, resumed video frames, and actual played audio-buffer counters. It reports commit-to-three-presented-frames and sustained A/V recovery separately; these include polling/decoder/buffering delays and are not physical display latency. Its SMB cases require the `/samples` mount below. Samples are test-only assets, never packaged into the production app.

Latest regression validation on the physical Pixel 9 Pro: **240 unit tests and 60 targeted device tests passed** on the final build, across three device runs. Both supplied videos completed 100 combined seek operations locally and through the loopback Samba fixture, including rapid paused bursts, with continued video and played audio buffers. The real-world MP4 measured **551 ms local / 1002 ms SMB median** commit-to-three-presented-frames; maxima were **2721 / 2838 ms**. These include decoder/polling/buffering delays, not physical scanout, and do not characterize the user's NAS. Aspect tests cover the MKV's 4:3 image, previews, rotated fit/fill/stretch, and recreation. An earlier SMB lifecycle run timed out; its isolated and final reruns passed. Lint: zero errors, 13 warnings.

Earlier synthetic seek validation measured **35 ms** for a warmed adjacent-frame gesture and **195 ms median / 210 ms maximum** for six precise long-GOP seeks, including PixelCopy observation overhead. The 60 fps fixture rendered at **59.92 fps with blur**, with callback-to-swap maximum **6.19 ms** in that sample. These synthetic/local-fixture results are not NAS/network, arbitrary-codec, or physical scanout guarantees.

Physical Pixel 9 Pro validation: all ten GPU/playback tests pass, including paused rotation and buffer teardown. Measured cadence was 23.98 fps for 23.976 fps media, 36.33 fps at 1.5× speed, and 59.92 fps for 60 fps media with blur enabled (59.96 fps without blur). These are short synthetic-fixture measurements, not a guarantee for every codec/resolution/device. The Android 17 emulator showed inconsistent cadence and eventually crashed in Android hardware-renderer cleanup during the full suite; the latest full emulator run is therefore incomplete. No tests or assertions were disabled to bypass those failures.

The full device suite includes `SmbIntegrationTest` and requires the disposable Samba fixture below. Start Docker Desktop and an Android emulator, then run these commands from the project root. The fixture shares only generated container data, is read-only to clients, and binds only to host loopback. Its account (`smbtest` / `fixture-password`) is **test-only**; do not substitute real credentials.

```powershell
docker build -t big-smb-test:local tools\smb-test
docker run --rm -d --name big-smb-test -p '127.0.0.1:1445:445' --mount "type=bind,source=$($PWD.Path)\app\src\androidTest\assets\player-test.mp4,target=/seed.mp4,readonly" --mount "type=bind,source=$($PWD.Path)\app\src\androidTest\assets,target=/samples,readonly" big-smb-test:local
.\gradlew.bat :app:connectedDebugAndroidTest
docker stop big-smb-test
```

The default emulator fixture address is `10.0.2.2:1445`. A device using `adb reverse tcp:1445 tcp:1445` can instead pass `'-Pandroid.testInstrumentationRunnerArguments.smbTestServer=127.0.0.1:1445'` to Gradle. The fixture includes account-only `Media`, guest `Public`, and inaccessible `Denied` shares, nested/empty folders, and a video name containing spaces, symbols, and Unicode. A 32 MiB zero-padded copy exercises speculative reads beyond the small test video's normal playback buffer.

`app\src\androidTest\assets\player-test.mp4` is a synthetic test pattern and tone, not production media. Recreate it with FFmpeg (remove only this generated asset first, or choose another output name):

```powershell
ffmpeg -hide_banner -loglevel error -nostdin -n -f lavfi -i 'testsrc2=size=160x90:rate=10' -f lavfi -i 'sine=frequency=440:sample_rate=22050' -t 30 -c:v libx264 -preset ultrafast -crf 35 -pix_fmt yuv420p -g 10 -c:a aac -b:a 24k -movflags +faststart 'app\src\androidTest\assets\player-test.mp4'
```
